# Kneekura-Stories 軽監査（2026-11-06）

対象: PR #1 の初期実装。文学作品の優劣ではなく、制作工程・保存・監督権限・共同運用を監査。

## 総監督の方針変更
- AIによるアイデア大量収集・自動選抜を**無期限休止**。旧機能のコードを消さず、復活には総監督の新たな明示指示とコード変更が必要。
- 総監督がClaudeやChatGPTと**個別に相談**して決めた企画を `ideas/director-brief.md` に記録。AIは企画の大量生成を開始しない。
- `IDEA_COLLECTION_ENABLED = False` を固定。旧 `--pick` は休止中に利用できない。

## 修正した問題
1. **提出後のファイル変更で差戻し不能**：承認時のハッシュ検証は維持。差戻しでは変更の有無を記録した上で作業状態に戻し、再提出できるようにした。
2. **完成原稿が欠けていても提出可能**：`drafts/chapters` にある実体のある章ファイル名が、`manuscript` に揃っていることを検査。足りなければ提出を拒否する。意図的な統合・削除には別途監督による調整が必要。

## 残る制約（未修正）
1. `--confirm-director` は本人認証ではない。運用規則でAIの無断使用を禁じるが、CLIだけでは本人の指示を技術的に証明できない。
2. 同じ作品を複数AIが同時編集する際の排他制御は未実装。現時点では担当章を明示し、ブランチや差分で衝突を避ける。
3. 監督が意図的に章を統合・廃止した場合の原稿整合性処理は未実装。未収録章を拒否する安全側の実装を優先した。
4. GitHub Actionsのユニットテストは制作管理の整合性を検査するもので、日本語小説の長編執筆品質やClaude・ChatGPT間の実運用を証明するものではない。

## 監査の範囲
- 機能削除なし。自動審査員、敵対的編集、Elo、自動改稿ループは導入しない。
- 外部のモデルAPI課金を必須にしない。
- 次回は実際に小さな企画を登録してから、章執筆と他AIへの引継ぎを試験する。
